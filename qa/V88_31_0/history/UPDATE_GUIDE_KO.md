## 1. 이번에 실제로 개선한 부분

### 인보이스 생성·조회 안전성

발행일, 지급 조건, 직접 지정한 지급기한, 선택 정산기간, 직접 입력한 인보이스 번호 기능을 유지했습니다. 전월 선택/선택 연도 전체 선택 버튼을 추가했습니다. 시작 월이 종료 월보다 늦으면 항목 옆에서 안내합니다. 직접 지정한 지급기한은 발행일을 바꿔도 유지합니다.

조회 중 취소가 가능하며, 취소한 요청의 늦은 응답은 새 인보이스를 덮어쓰거나 다음 요청의 버튼 상태를 풀 수 없습니다. 취소는 **이번 결과의 적용 중지**입니다. 서버에서 진행 중인 읽기 요청 자체를 취소했다고 보장하지 않습니다.

공통 인증·데이터 계층의 변경 알림/리비전 또는 현재 계정·선택값이 달라지면 이전 출력물을 잠그고 다시 생성하도록 했습니다. 조회 도중 변경된 경우도 결과를 버립니다. 이 기능은 현재 브라우저가 감지한 변경을 보호합니다. 다른 사용자의 원격 변경을 실시간으로 감시하는 서버 알림 기능을 새로 만든 것은 아닙니다.

서버 응답에 성공 여부가 없거나 자료형이 잘못된 경우 성공으로 간주하지 않습니다. 인보이스 월별 자료는 순서 정리, 월 자료형, 존재하지 않는 행의 비정상 금액을 추가로 검사합니다. 기존 스프레드시트의 공백 포함 숫자 월 값은 호환 유지합니다. 기존에 지원하던 지연 집계값의 POS/배달 합계 대사 방식도 유지합니다.

### PDF·인쇄 안정화

**실제 Chromium 인쇄에서 화면 진입 애니메이션의 초기 투명도가 남아 빈 PDF가 나오는 문제를 발견하여 수정했습니다.** 인쇄에서는 화면 애니메이션·가림 상태를 해제하며 표가 다음 페이지로 넘어가도 행과 표 머리글을 유지합니다. 준비되지 않은 이전 인보이스를 Ctrl+P로 출력하면 이전 금액 대신 재생성 안내를 표시합니다.

PDF 다운로드 준비는 입력값을 잠근 상태에서 독립된 문서 복사본으로 진행합니다. 중복 클릭, 중간의 데이터 변경, 글꼴/이미지 준비 실패, 렌더링 실패, 대기 시간 초과 시 화면 상태와 임시 요소를 정리합니다. PDF 준비 기본 제한은 60초입니다.

준비 중 취소 후 늦게 렌더링이 끝나더라도 파일 저장을 시작하지 않습니다. 저장은 렌더링과 분리한 마지막 단계에서 상태를 다시 확인한 뒤 수행합니다. **이미 브라우저에 저장 요청이 전달된 파일은 취소로 되돌릴 수 없습니다.** 취소된 외부 렌더러의 계산이 내부적으로 즉시 중단된다고 보장하지 않으며, 해당 결과를 저장하지 않는 방식입니다.

### 화면·안내 문구

‘발송 전 확인’ 패널에 정산기간, 대상 매출(CAD), 청구 수수료(CAD), 지급기한, 토론토 기준 조회·대사 시각을 표시합니다. 작성 전/조회 중/검증 완료/재생성 필요/확인 필요 상태를 구분합니다.

월 자료가 응답에 없으면 누락 월을 표시합니다. **응답 누락은 매출 0원 확정과 다릅니다.** 선택 기간에 모든 월이 없더라도 서버가 반환한 값 자체를 0원으로 꾸며 넣지 않습니다. 이 경고가 있으면 발송 전에 원본 매출을 확인해야 합니다.

과거 지급기한 또는 미래 발행일에는 별도 안내를 표시합니다. 과거 지급기한 경고는 미입금 판정이 아니며 미래 발행일 지정은 예약 발행 기능이 아닙니다.

흰색·네이비와 기존 브랜드 포인트 색상을 유지하면서 요약 카드, 입력 안내, 상태 배지, 취소 버튼을 정리했습니다. 작은 화면에서는 입력 패널이 한 줄로 이어지고, A4 문서만 내부에서 좌우로 스크롤됩니다. 전체 페이지의 가로 넘침을 줄였습니다.

### 배포 전 자동 검증

기존 `SINJEON verified Pages deployment`의 수동 배포 정책은 유지했습니다. 새 `SINJEON source validation`은 push/PR/수동 실행 시 **검증만** 수행합니다. Pages 쓰기 권한이나 자동 배포 단계는 없습니다.

Node 회귀시험은 추가된 `tests/*.test.js`까지 함께 실행합니다. 기존의 배포 파일 수를 고정값으로 비교하지 않는 BuildFix도 유지합니다. 사이트 파일은 검증된 목록과 해시로 준비하며 테스트·QA 보고서는 운영 공개 파일 목록에 넣지 않습니다.

5. 기존 앱에 새 버전 안내가 나오면 정상 갱신 흐름을 사용합니다. 해결 목적으로 저장소 전체 초기화, 미전송 주문 삭제, 데이터베이스 초기화를 하지 마십시오.

원본 검사 대상 저장소는 `eunbeenlee/y2c-advisory-portal`, 도메인은 `partner.sinjeoncanada.com`입니다. 연결은 임의 변경하지 않았습니다. CNAME·Apps Script 주소·Android APK·앱 인증서를 그대로 유지했습니다. 이 업데이트는 네이티브 APK 재빌드가 아닙니다.

## 4. 검증하지 않은 범위 — 중요

이번 브라우저 검사는 실제 Chromium에 저장소 HTML/CSS/JS를 메모리 문서로 올려 렌더링했습니다. 업무 API·로그인 계정·매출은 **가상 자료**이고 외부 네트워크는 차단했습니다. 사이트 URL로 이동하는 운영 환경 전체 검사는 아닙니다.

**실제 네이티브 인쇄 PDF는 생성·페이지 렌더링·본문을 확인했습니다. 반면 ‘PDF 다운로드’의 외부 html2pdf/html2canvas/jsPDF 렌더링 엔진은 이 환경에서 가져올 수 없어 모의 엔진으로 제어 흐름만 시험했습니다.** 두 검증을 같은 것으로 주장하지 않습니다. 운영 CDN 로딩과 실제 다운로드 PDF는 배포 후 확인해야 합니다. 차트 외부 라이브러리 렌더링도 이번 검증 범위 밖입니다.

Apps Script 백엔드 소스가 없으므로 실제 서버 응답 형식, 권한 강제, 원자적 중복요청 방지, 동시 수정 충돌, 재고 예약·차감·취소 복원, 메일 발송, 수금·입금 확인, 서버 인보이스 대장 저장은 검증하거나 변경하지 않았습니다. 서버에서 `success`를 문자열 등 비표준 값으로 반환한다면 현재 프런트엔드는 성공으로 처리하지 않으므로 서버 형식을 확인해야 합니다.

실제 GitHub Actions 클라우드 실행, 호스팅 라우팅, 서비스워커 설치·업데이트, iOS/Android 실기기와 앱 동작은 검증하지 않았습니다. 원래 포함된 jsdom 시험은 이번에 실행하지 않았고 검증 수치에 포함하지 않았습니다. 실제 운영 데이터 변경이나 배포는 수행하지 않았습니다.

인보이스의 기존 0% 세율, 주문의 지역별 계산, 지급 계좌는 바꾸지 않았습니다. 이것은 세무 적정성 검토가 아닙니다. 공통 config와 실제 주문 모듈의 기존 세율 표 차이는 서버 기준을 확인해야 하므로 임의로 통일하지 않았습니다.

## 5. 재현 명령

Python 3.10 이상과 Node가 실행되는 환경에서 프로젝트 루트 기준:

```sh
python tests/verify-release.py
```

모든 결과와 임시 스테이징은 소스 폴더 바깥 임시 경로에 생성됩니다. 다른 경로를 지정할 수 있으나 소스 폴더 내부는 재귀 복사를 막기 위해 거부합니다.

```sh
python tests/verify-release.py --output /tmp/sinjeon-verification
```

브라우저 소스 검사는 Python의 `playwright`, `beautifulsoup4`, `PyMuPDF`와 설치된 Chromium을 사용합니다. Playwright 패키지와 브라우저는 별도 설치 요건이며 이번 프로젝트의 운영 의존성으로 추가한 것은 아닙니다.

```sh
python tests/source-browser.py --browser /usr/bin/chromium --output /tmp/sinjeon-browser-qa
```

이 명령은 공개 사이트에 접속하지 않습니다. 원본 네트워크 기반 브라우저/DOM 시험도 `tests/`에 보존했으나 환경 준비 후 별도로 실행해야 합니다.

향후 공개 파일을 추가·수정하면 새 버전으로 목록과 해시를 갱신한 후 다시 검증합니다. 기존 배포 검사를 삭제하거나 숫자만 바꾸어 통과시키지 마십시오.

```sh
python .github/checks/seal_release.py --version V88_32_0
python tests/verify-release.py
```

새 공개 자산은 `--add assets/...`로 명시합니다. 이 명령들은 파일 검증 준비일 뿐 배포 명령이 아닙니다.
